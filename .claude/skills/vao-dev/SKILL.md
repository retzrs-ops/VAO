# VAO 開発の進め方

VAO は Retzn さんが配布する Windows 向けの **OBS ネイティブ音声フィルタ**（VST3 ではない）。
利用者が画面の定型文を読むと、声と部屋を分析して、ゲイン・ノイズゲート・EQ・コンプ・ディエッサー・リミッターを自動で設定する。
利用者は素人の配信者が中心。

## 0. 会話のルール（毎回守る）

- 説明は**必ず日本語**。専門用語は短く言い換える。
- 実機（Windows の OBS）で確かめていないことは、正直に「未確認」と書く。
- 手順は番号付きで、Retzn さんが何をすればよいかを具体的に書く。
- ログは要点の行だけ貼ってもらう（エラーの前後、OBS ログの `[VAO]` の行など）。

## 1. 始め方（トークン節約）

**Claude Code のとき**
1. 作業フォルダは `C:\Users\retz_\claude\VAO\`（1つに固定）。過去の版は `C:\Users\retz_\claude\old\`。
2. **`引継ぎ資料.md` だけを最初に読む。** 「コードの地図」で該当ファイルを決め、そのファイルだけ開く。

**claude.ai のチャットのとき**
1. Google Drive の `マイドライブ\VAO\引継ぎ資料.md` を読む（Google Drive コネクタ）。
2. コードが必要なら、そのファイルだけ貼ってもらうか、Claude Code での作業に切り替えるよう提案する。

長い会話は重くなる。区切りの良いところで引継ぎ資料を更新し、新しいスレッドへ移るよう提案する。

## 2. 版上げの手順

1. `git status` で未コミットの変更がないことを確かめる。
2. 前の版のソースを `old\VAO_v<前の版>.zip`（中に `VAO_v<前の版>\` フォルダ）として残す。
   `git archive --format=zip --prefix=VAO_v<前の版>/ v<前の版> -o ..\old\VAO_v<前の版>.zip`
3. 修正する。版を上げるときは次をそろえて更新する。
   - `buildspec.json` の `version`（版番号はここが正。コードに直接書かない）
   - `CHANGELOG.md` の先頭に開発者向けの変更点（ソースファイルの先頭には書かない）
   - `Readme.txt`（利用者向け。`Version:` 行と「バージョン履歴」の先頭に追記）
   - `引継ぎ資料.md`（コードの地図・版の表・未確認/残課題・次にやること）
4. テストに新しい動きのテストを足し、`tools\test.bat` で FAIL 0 件を確認する。
5. コミットする。**push・タグ付け（`v<版>`）・リリース公開は Retzn さんの確認を取ってから。**
6. タグを push したら `gh run watch` で GitHub Actions のビルド成功を確かめる。
7. Google Drive の `マイドライブ\VAO\` に、`引継ぎ資料.md`・`old\` の新しい ZIP・`release\` のインストーラーをコピーする。

## 3. ファイルの規約

| ファイル | 規約 |
| --- | --- |
| `src\` のソース | 先頭2行は `// SPDX-License-Identifier: GPL-2.0-or-later` と `// Copyright (c) 2026 Retzn (VAO - Voice Auto Optimizer)`（版番号は入れない） |
| `src\dsp\` | **OBS・Qt に依存しない**純粋な C++。将来 VST3 版と共有するため。`obs-module.h` を include しない |
| `src\obs\` | OBS との境目だけ。音声処理の中身は書かず `dsp` を呼ぶ |
| `Readme.txt` | **利用者向けのみ**。ビルド・テスト・Git の話は書かない。前回に加筆修正（書き直さない）。UTF-8・BOM なし・LF |
| `tools\*.bat` | **Shift_JIS（cp932）＋ CRLF**。`( )` ブロック内の echo に半角 `)` を入れない |
| `data\locale\*.ini` | 画面の文字はすべてここ（コードに日本語を直接書かない）。`ja-JP.ini` を先に、`en-US.ini` も同時に更新 |
| `LICENSE` | GPL-2.0（テンプレート由来。消さない） |

バッチを編集するときは、cp932 で読み込み → 置換 → cp932 で書き戻す（CRLF を保つ）。

## 4. テスト

- `tests\` の音声処理テストは OBS なしで動く（ctest）。テスト用の音（正弦波・無音・ノイズ・大音量）はコードで作り、音声ファイルを同梱しない。
- 確かめる観点: リミッターが上限を超えない、無音でゲートが閉じる、キャリブレーションが同じ入力から同じ設定を出す、44.1kHz / 48kHz・1〜8ch で壊れない。
- ビルド後、`tools\install_local.bat` で `C:\ProgramData\obs-studio\plugins\` に入れ、OBS での確認は Retzn さんに頼む。

## 5. 設計上の決まり（壊さないこと）

- **音声処理スレッドでは、メモリ確保・ロック・ログ・ファイル操作をしない。** バッファは設定変更時に確保しておく。
- OBS の音声は float の planar（チャンネルごとの配列）。チャンネル数とサンプルレートは毎回 OBS から受け取り、決め打ちしない。
- **初回公開後は、フィルタ ID と設定キーの名前を変えない**（利用者のシーンに保存された設定が消えるため）。増やすときは新しいキーを足す。
- 入力の時点で音割れしているものはデジタルでは直せない。キャリブレーションで見つけたら「マイク側のゲインを下げてください」と警告する。
- 処理の順番: ハイパス → ノイズゲート → EQ → コンプ → ディエッサー → 出力ゲイン → リミッター（最後は必ずリミッター）。
- 更新の確認は**しないか、利用者がオンにしたときだけ**。起動のたびに通知を出さない（Retzn さんが atkAudio で嫌だった点）。

## 6. 決定済みの方針（蒸し返さない）

- **OBS ネイティブのフィルタ**として作る。atkAudio などの VST3 ホストに依存しない。
- VST3 版は後回し。やるときは `src\dsp` を共有して別ターゲットとして出す。
- ライセンスは **GPL-2.0-or-later**（OBS にリンクするため）。ソースは GitHub で公開する。
- 最初の版（0.1.0）は「キャリブレーション＋ゲイン＋リミッター」だけ。残りの処理は動作を確かめてから足す。
- 配布の形（無料／有料）は**未確定**。ひとまず無料配布の前提で進める。
- 名前は **VAO – Voice Auto Optimizer**（OBS のフィルタ表示は「VAO Voice」、リポジトリ・フォルダは「VAO」）に決定。公開前に J-PlatPat で商標を確認する。

## 7. Retzn さんの環境（参考）

- Windows 11（Windows 10 も対象）、Visual Studio 2022、OBS Studio 最新版。
- AMD Radeon RX 9070 XT。WaveLink を使用（VAO との配線はまだ聞いていない）。
